# 本机巡检说明（方案 A · 不联网，替代 agent-autoloop 三条 cron）

> 版本 v1 · 2026-11-13 · 维护：DSH（主理人）

## 一、为什么有这个

原计划把三条巡检规则（`WF-每日巡检` / `WF-待验提醒` / `WF-回执跟进`）交给开源中台 agent-autoloop 跑，但它的安装脚本和发布包在 GitHub，本机直连不通、要走代理，且代理不是常开。
老板选了**方案 A**：不装中台，用**本机 Windows 计划任务 + Python 脚本**实现同样三件事，全程不联网。

## 二、三条检查

| 计划任务 | 频率 | 命令 | 检查内容 |
|---|---|---|---|
| AI聊不停-WF每日巡检 | 每天 08:00 | `巡检.py --daily --toast` | 工单状态计数、项目数、待签收、失败单、备份状态；写 `巡检\每日_YYYY-MM-DD.md` |
| AI聊不停-WF待验提醒 | 每 2 小时（08:30 起） | `巡检.py --pending --toast` | `status=待验` 的单（单号/标题/执行端/已等分钟），有则弹通知（同批不重复弹） |
| AI聊不停-WF回执跟进 | 每 15 分钟 | `巡检.py --outbox --toast` | 派发中 >10 分钟、已回件 >30 分钟视为停滞；失败单报最近 10 条；有则弹通知 |

任务均为**当前用户登录时运行**（Interactive），注销/关机不跑；重启后自动生效。

## 三、手动用法

```powershell
cd <仓库目录>
python 巡检.py --once            # 三项都跑
python 巡检.py --daily --toast   # 只跑每日 + 弹通知
python 巡检.py --pending --no-toast
python 巡检.py --outbox
```

计划任务管理：

```powershell
schtasks /Query /TN "AI聊不停-WF每日巡检" /V /FO LIST   # 查看
schtasks /Run   /TN "AI聊不停-WF每日巡检"               # 立即跑
schtasks /Change /TN "AI聊不停-WF每日巡检" /DISABLE     # 停用（/ENABLE 恢复）
schtasks /Delete /TN "AI聊不停-WF每日巡检" /F           # 删除
```

## 四、输出文件（`桌面端\巡检\`）

- `每日_YYYY-MM-DD.md` —— 当天覆盖写；内容：工单状态、项目数、最近群消息、备份状态、待签收、失败单。
- `巡检.log` —— 追加日志，>5MB 自动轮转为 `巡检.log.1`。
- `state.json` —— 去重状态（待验提醒同批只弹一次；记录 last_daily），可安全删除（删后下次会重新弹）。

## 五、只读与安全

- 巡检**不写真实台账**：先把 `数据\台账.sqlite3`（含 `-wal`/`-shm`）复制到临时目录，再只读查询。
- 不代签、不改工单状态、不写记忆库、不调模型；只弹通知 + 写 `巡检\` 下文件。
- 依赖：Python 3.12（Windows 下用 `python.exe`，macOS/Linux 用 `python3`），仅标准库。

## 六、已知局限

- 只是"提醒"，不会自动推进/签收；真正处理仍在 AI聊不停 界面。
- 失败单可能在多次重试后累积；可把阈值/条数改在 `巡检.py` 顶部常量区。
- 通知走 Windows 托盘气泡；系统关闭通知时不显示，但 `巡检.log` 仍记录。
- 若以后要"发到群聊/自动建任务"，需要平台接口改造，另议。
