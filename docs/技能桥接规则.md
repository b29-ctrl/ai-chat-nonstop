# 技能桥接规则（通用版）

> 适用：工单调度台 v0.6+。目的：任何 AI/客户端装了什么技能，都能按同一套规则判断「调度台能不能直接用、要不要桥接」。
> 核心原则：**技能装到执行端，调度台不装技能、只下发指令。**

## 一、先记三件事

| 字段 | 说明 |
|---|---|
| `skill_id` | 技能 ID/名称，例如 `dev-workflow-1n1n` |
| `installed_for` | 技能装在哪：DSH / WorkBuddy 客户端 / CodeBuddy CLI / COZE / 其他 |
| `adapter_runtime` | 调度台准备用哪个适配器执行：`dsh` / `workbuddy` / `coze` / `openai` / `a2a` / `webhook` / `process` |

## 二、找技能发现路径

| 运行时 | 技能发现位置 |
|---|---|
| DSH（`dsh headless`） | `~/.dsh/skills/<skill_id>/SKILL.md` |
| CodeBuddy CLI（WorkBuddy 适配器） | `~/.codebuddy` 的插件/技能配置（不是 WorkBuddy 桌面客户端的 `.workbuddy\skills`） |
| COZE 云端 Bot | 没有本机技能路径；只有 Bot 的 prompt / 知识库 / 插件 |
| OpenAI 兼容 / A2A / webhook | 没有本机技能路径；取决于远端是否声明支持技能 |

## 三、判定表

| 技能安装位置 | 调度台执行端 | 结论 |
|---|---|---|
| `~/.dsh/skills` | `dsh` | ✅ 无需桥接（同 profile） |
| `~/.codebuddy` 已启用技能/插件 | `workbuddy`（CodeBuddy CLI） | ✅ 无需桥接 |
| WorkBuddy 桌面客户端 `.workbuddy\skills` | `workbuddy`（CodeBuddy CLI） | ⚠️ **需 path 桥**：复制/软链 `SKILL.md` 到 CLI 技能目录 |
| 任意本机技能 | `coze` | ❌ 不可桥接（云端不能跑本地脚本）；只能改写为 Bot prompt/KB |
| 任意本机技能 | `openai` | ❌ 本地脚本不可；纯 prompt 可做 prompt 桥 |
| 远端 A2A/webhook 技能 | `a2a`/`webhook` | 看对端是否声明支持 skill；否则只能 prompt 桥 |

## 四、固定四步

1. **定位**：该适配器的技能发现路径；
2. **探测**：让适配器「列出当前技能」或扫描其技能目录；
3. **判定桥接类型**：
   - `none`：可见，直接用；
   - `prompt`：纯提示词/规范 → 注入 `prompt_prefix` 或工单；
   - `path`：本地脚本技能且执行端能跑本机命令 → 复制/软链到执行端技能目录；
   - `api`：远端声明支持 skill → 按协议调用；
   - `impossible`：云端 + 本地脚本 → 换方案；
4. **实测**：明确说「使用技能 X」，确认真的用了，而不是「装了但没触发」。

## 五、硬规则

1. 技能装到能执行它的客户端，**不要装进调度台目录**；
2. 调度台只负责「可见性探测 + 桥接判断 + 下发指令」，不复制技能代码；
3. **有技能 ≠ 会自动用**：消息/工单里要写「使用技能 X」；
4. WorkBuddy 桌面客户端技能默认不等于 CodeBuddy CLI 可见，必须单独验证；
5. 每次下发前记录：技能 ID、安装位置、执行端、桥接类型、验证结果——方便别人接手。

## 六、给使用者的最小说明

你只需要告诉调度台维护者：

```
客户端：DSH / WorkBuddy / COZE
技能名：xxx
```

维护者按本规则判断：**无需桥接 / 需 path 桥 / 只能 prompt 桥 / 不可桥接**，再下发指令。
