# GitHub 适配器/编排平台调研（2026-11-10）

> 目标：给「单机 Windows、文件即工单、本机 CLI AI（CODEX/DSH/WorkBuddy）+ 云 API（COZE）+ 拉取端（豆包）」找一个**能直接用的适配器/编排平台**，再决定桌面端怎么做。
> 数据来源：GitHub REST API（stars/license/language/archived）与各仓库 README。

## 结论

1. **没有现成平台直接匹配**「文件工单 + 本地 CLI AI 适配器 + Windows 单人 + 零常驻服务 + 门禁台账」。n8n/Dify/Windmill 都要求引入一套服务端/数据库/多用户体系，反而把简单系统做重。
2. **最值得借鉴的两家**：
   - `golutra`：桌面多 Agent 工作台的交互（Agent 头像、实时日志、并行任务、点击查看）；
   - `agent-autoloop`：事件 → 规则 → CLI Agent → 审批卡片的闭环，正好对应「派单 / 等拍板 / 继续」。
3. **自建薄层**：Python 标准库 + SQLite（现有方案）+ 本桌面端（pywebview/Edge 窗口）；适配器按 `process/http/pull` 三类配置，产品名不写死。
4. 这样既拿到「随时沟通 + 看工单流转」的体验，又不引入任何第三方服务/云后端/新依赖（桌面壳 pywebview 是唯一可选安装）。

## 本桌面端对应的实现

- `桌面端\服务.py`：SQLite 台账 + HTTP API + SSE + 聊天适配器；
- `桌面端\web\`：沟通 / 工单 / 适配器 三页；
- `桌面端\启动.py`：本地服务 + pywebview 窗口（失败回退 Edge 应用窗口）；
- `启动桌面端.vbs`：双击启动。
