# 适配器接入指南（给 AI / 给接手的人）

> 适用：工单调度台 v0.6+。你（AI）收到这份文档后，按本流程给调度台**新增一个 AI 适配器**；不要改死代码，只改配置/启动路径，并做一次实测。
> 核心：**调度台是路由器，AI 是执行端。** 新增 AI = 在 `桌面端/配置.json` 里加一个适配器 + 在项目群里把它加进成员。

## 0. 你收到文档后先做什么

1. 先读 `README.md`、`桌面端/配置.json`、本文件；
2. 问用户 4 件事：
   - 要接的 AI 是什么（WorkBuddy / DSH / COZE / 其他）；
   - 它的 CLI/API 路径、模型、Key 在本机哪里；
   - 走哪个适配器类型（`workbuddy` / `coze` / `process` / `openai` / `a2a` / `webhook` / `pull` / `demo`）；
   - 这个 AI 属于哪个项目群。
3. 只改 `配置.json`（必要时加 secrets 文件），不改 `服务.py`/`app.js`；
4. 给用户一份**变更摘要 + 测试结果**，不要贴 Key。

## 1. 适配器字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 适配器 key | 是 | `adapters` 下的唯一 id，例如 `workbuddy2`、`my-ai` |
| `type` | 是 | `workbuddy` `coze` `demo` `process` `openai` `a2a` `webhook` `pull` |
| `enabled` | 是 | `true` 才会出现在沟通页 |
| `label` | 是 | 页面显示名 |
| `post` | 建议 | 岗位名（如“构建测试/DevOps”）；由 `岗位目录.json` 同源维护 |
| `role_id` | 建议 | 岗位 ID（如 `build_devops`）；派发器按岗位路由时用 |
| `default_model` | 视类型 | 默认模型 id |
| `models` | 视类型 | 静态模型列表；WorkBuddy 会动态刷新 |
| `command` / `stdin` / `output` / `result_path` | process 必填 | CLI 参数、是否 stdin、输出格式 |
| `url` / `token_env` / `timeout_s` | http 类 | COZE/OpenAI/A2A/webhook |
| `secret_env` | 是（有 Key） | 只允许引用 `paths` 里声明的文件/键，不能写死 Key |
| `enabled` | 是 | 字符串 `"false"` 也按关闭处理 |

> 完整字段以 `配置.json` 现有块为准；复制一个同类型块最省事。

## 2. 新增 AI：按类型操作

### A. WorkBuddy / CodeBuddy CLI

1. 确认本机 `codebuddy` 路径、`CODEBUDDY_API_KEY` 文件；
2. 复制 `adapters.workbuddy` 块，改 key/label；
3. `paths` 里加 `workbuddy2_cli` / `workbuddy2_key`；
4. `secret_env` 指向新路径（不要写 Key 字面量）；
5. `enabled: true`；
6. 重启调度台（VBS），在「适配器」页确认状态，在「沟通」发一句「回复 OK」。

### B. 任意 CLI（process）

1. 确认 CLI 支持非交互参数，例如 `mycli --prompt "..."` 或 stdin；
2. 配置：
   ```json
   "my-ai": {
     "type": "process",
     "enabled": true,
     "label": "MyAI（自研）",
     "command": ["{my_cli}", "--prompt", "{prompt}"],
     "stdin": false,
     "output": "text",
     "timeout_s": 300,
     "cwd": "{project}",
     "secret_env": {"MY_KEY": {"file": "{my_key_file}", "key": "MY_KEY"}}
   }
   ```
3. `command[0]` 必须在 `paths` 值或 `security.process_allowed_executables` 白名单里；
4. 不允许 `--dangerously-*` / `--bypass` / `--no-sandbox` / `--skip-permissions`。

### C. COZE / OpenAI / A2A / webhook

1. 复制同类型块，改 key/label/url/token；
2. COZE 的模型绑定在 Bot 上，换模型去扣子后台改 Bot → 发布；
3. `openai` 的 Key 不要写进 `配置.json`，用 `secret_env`；
4. 本地测试地址必须显式 `allow_local: true`（默认强制 https、禁环回/私网/重定向）。

### D. 演示

`demo` 不需要 Key；用于先看项目群/工单界面。

## 3. 重启与验证

1. 关掉旧窗口，双击 `启动桌面端.vbs`；
2. 「适配器」页应出现新 AI；
3. 发一条低风险测试消息，确认不是 `未配置/未接入/超时`；
4. 打开「项目管理」→ 当前项目 → 「AI 成员」→ 勾选新 AI → 保存；
5. 回「项目群」，确认新 AI 出现在「群内 AI」；
6. 新建一张工单（自动归到当前项目），项目群应出现一条**摘要**动态（不显示 AI 正文）。

## 4. 新建项目 / 重命名 / 把 AI 拉进同一个群

1. 顶部「项目管理」或项目群的「+ 新建项目」；
2. 填项目名 → 新建；
3. 选中项目 → 「重命名」保存；
4. 「AI 成员」勾选要进群的 AI → 保存；
5. 项目群输入框上方可 **@全部 / @单个 / @多个**；发群消息后，被 @ 的 AI 各自回复；
6. 自动派单摘要也落在这个群里：收到工单 / 准备派单 / 已派单 / 已回件 / 门禁已签 / 派单失败；系统摘要不含 AI 正文；
7. AI 回复完整显示、自动换行；群消息区自己滚动，不再截断气泡。

## 5. 技能怎么处理

技能不装调度台，装执行端。判定：

| 技能装在哪 | 执行端 | 结论 |
|---|---|---|
| `~/.dsh/skills` | DSH | 无需桥接 |
| `~/.codebuddy` 已启用 | WorkBuddy CLI | 无需桥接 |
| WorkBuddy 客户端 `.workbuddy\skills` | WorkBuddy CLI | 需要 path 桥 |
| 本机技能 | COZE/云端 | 不可桥接，只能 prompt/KB |

详见 `技能桥接规则.md`。

## 6. 安全红线

- 不把 Key/Token 写进 `配置.json`、聊天、工单、截图；
- 不把 `process` 的 command 改成任意 shell/下载执行；
- 不把 `paths.project` 指向用户没授权的目录；
- 上传附件只存本机，不自动外发；
- 不直接改 SQLite 台账里的真实工单状态来“演示成功”。

## 7. 给 AI 的最终产出格式

```text
新增 AI：<label>（<type>）
改的文件：桌面端/配置.json（+ 可选 secrets 文件）
需要用户确认：<路径/Key/模型>
测试：沟通页发「回复 OK」→ 结果 <通过/失败 + 错误>
项目群：已加入 <项目名>，成员数 <n>
未做/风险：<...>
```

> 用户把这份文档丢给你时，按第 0 节先问 4 个问题，再动配置；不要凭产品名猜路径。
